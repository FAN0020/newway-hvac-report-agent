# `haoqi` 分支交付说明

本分支按照 [冻结契约](WORK_ORDER_REPORT_CONTRACT_V1.md) 实现一条本地可操作的维修记录流程。

## 怎么使用

1. Manager 在 **Templates → New template** 上传模版，审核系统提议的字段，并为每个字段设置必填条件、类型、允许来源及确认要求。审核、知识资料决定和契约检查完成后发布版本。已发布版本不能原地改写。
2. 开工前如有工单，可在 **New report** 上传 `.txt`、`.csv`、`.md` 或 `.docx` 工单。系统提出工单号、稳定车辆 ID 等候选，人工核对后才可选用。没有工单也可以直接开始报告。
3. 技工选择模版后，录入前即可看到完整字段清单与逐字段来源建议。来源建议受 manager 规则约束；配置本地 Ollama 时模型可在合格来源中建议，未配置或输出无效时界面标明规则回退。模型不能改动必填规则。
4. 技工口述或输入后，原始转录保留。关键文字修正需要复核；字段候选需要可追溯证据。系统立即列出仍缺的必填技工信息并逐项提问。补答写回同一报告会话，重新验证后才可复核和确认。
5. 确认报告形成不可变快照。带工单的报告用人工核对的车辆 ID 进入车辆历史；无工单的报告确认后可在 **Reports → Review vehicle identity and history** 独立核对稳定车辆 ID，再关联历史。历史与结构化 JSON 导出读取确认快照。

## 知识库与工单的界限

Manager 上传的自定义模版文本知识资料现在会在相应的模版版本内检索，并展示带文档来源的规范片段。知识库可以用于规范、术语和追问提示；片段不会自动写成这次维修的动作、零件、测量、测试或安全事实。规范字段仍须技工核对后输入。非文本知识文件需要人工处理，系统不会假称已检索。

工单资料只能为模版明确允许 `WORK_ORDER` 的字段预填。车辆历史使用核对后的稳定车辆 ID，不靠车牌、型号或口述猜测合并。

## 验收与已知边界

- `npm run check`：整合后 740/740 通过。
- `npm run accept:batch3`：覆盖 20 字段、8 个必填、一次录入提取 6 个、即时列出剩余 2 个及补答。
- `npm run accept:batch3:model`：在安装本地 `qwen3.5:9b` 时可复现真实来源选择；模型建议仍由服务器规则和证据校验。
- 浏览器验证：20/8/6/2 界面流程、补答后刷新恢复；整合后的模版设置、字段清单及车辆核对页面入口。

本分支只实现 ServiceScribe 本地持久化与导出。没有连接 SBS Transit 内部系统，也没有导入既有车队历史；备份、保存期限、生产身份权限和正式对接接口仍需真实部署方确定。合成用例与本地浏览器验收不能证明现场识别准确率。详见各批次验收记录。
