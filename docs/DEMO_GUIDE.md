# 明天演示指南

## 明天建议使用的演示方式

当前最可靠的路径是让服务运行在演示电脑上，并把页面开放给同一可信 Wi-Fi 的其他设备。本机已在项目内准备好并通过了真实 `whisper.cpp` Provider 冒烟测试；但真实中文 HVAC 口述和浏览器麦克风尚未完成现场验收，所以仍必须保留手动文本兜底。手机和异机浏览器在普通 HTTP 页面通常也无法取得麦克风权限。

当前页面已连通“服务端词表候选 → 原文/建议文本并排显示 → 技师逐项接受或拒绝 → correction receipt → 事实提取”。修复规则和准确率只由合成测试验证；演示时不宣称真实语音纠错准确率或生产可用性。

### 先选演示模式

- **只在演示电脑上用（最稳）：** 运行 `TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm start`，打开 `http://127.0.0.1:4310`。不需要手工设置 token。
- **让同一 Wi-Fi 的其他设备打开：** 按下文生成一次性 token，再运行 `npm run demo`。这是受控 LAN 演示，不是公网部署。

### 演示前 10 分钟

1. 在项目根目录先验证真实 Whisper Provider，再做全量检查：

   ```sh
   npm run stt:smoke
   TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm run check
   ```

   如果是新克隆的 Mac，先运行 `TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm run stt:prepare`。该步骤会下载约 148 MB 的 Base 模型并在项目内构建运行时，不要留到上台前才执行。

2. 在 zsh 中隐藏输入一个本次专用的临时口令。口令至少 16 位，必须同时含字母和数字或符号：

   ```sh
   read -s "HVAC_DEMO_TOKEN?Temporary demo token (16+ characters): "
   echo
   export HVAC_DEMO_TOKEN
   TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm run demo
   ```

   服务如果没有口令或口令太弱会拒绝启动；启动日志不会显示口令。

3. 由演示者自己在另一个终端或系统网络设置中查看这台电脑的 LAN IP。程序不会自动读取网络接口。macOS Wi-Fi 常用命令是 `ipconfig getifaddr en0`；如果为空，就从“系统设置 → 网络”查看。
4. 主机浏览器打开 `http://127.0.0.1:4310`，其他设备打开 `http://<LAN-IP>:4310`。两边都输入同一个临时口令。仅在可信 Wi-Fi 使用，不要做路由器端口转发或公网暴露。
5. 点击“填入合成演示文本”。它只填文本，不会自动提交。演示文本特意包含两个受控修复候选：

   > 客户反映不制冷。检查发现运刑电容损坏。更换了一个三十五微法电容。试机运行正常。问题已解决。建议下次保养清洗滤网。

6. 点击使用手动原文，再点击“检查术语修复候选”。
7. 在并排视图中对比原文和建议文本：逐项接受或拒绝；“三十五微法 → 35 µF”需要另外勾选关键值已人工核对。输入技师姓名/ID，确认修复决策后才会生成报告。
8. 演示时重点指出：

   - 页面保留了原始文本；
   - 每条报告事实都能回到一个服务事实 ID；
   - Validator 显示来源覆盖率和缺失字段；
   - 未勾选技师确认前，保存和导出按钮不可用；
   - 确认绑定当前报告哈希，修改内容后需重新校验和确认。

9. 在报告复核区勾选复核，再确认当前报告版本。
10. 点击保存 JSON 或导出文本。这些运行数据保存在演示电脑的 `data/reports/`，不会被 Git 跟踪。
11. 结束后按 `Ctrl-C` 停止服务，并运行 `unset HVAC_DEMO_TOKEN`。不要复用本次口令。

## 网络和麦克风的现场预期

- 局域网页面使用 HTTP，不是 HTTPS。多数手机和异机浏览器会把它视为非安全上下文，因此页面会停用“开始录音”并提示改用 WAV 上传或手动文本。
- 主机浏览器通过 `http://127.0.0.1:4310` 访问时通常仍可使用麦克风。真实 CLI/Provider 已用官方英文 WAV 跑通，但真实浏览器授权和中文 HVAC 口述仍需明天现场彩排；演示前仍应以手动文本作为保底。
- 如果要展示“多人可访问”，可以让主机浏览器操作、第二台设备观看页面；也可以让第二台设备走手动文本流程。不要声称移动端语音已经验证。
- 所有 `/api/*` 都需要 bearer token；错误口令会清除当前标签页中的会话口令并要求重输。Token 只存在于当前 shell/服务进程和浏览器标签页的 sessionStorage/内存，不进 URL、localStorage、日志或报告。
- 服务只接受同源浏览器请求和私有 LAN 地址（或显式允许的本地主机名），不返回宽松 CORS。这仍不是公网级身份或传输保护。

## 故障切换表

| 现场问题 | 立即切换 |
|---|---|
| 麦克风没有权限或按钮不可用 | 改用主机 `127.0.0.1` 页面；仍失败就用“手动输入原文” |
| Whisper health 不可用 | 不要临场下载；改走手动文本全流程 |
| 手机/异机无法打开页面 | 回到主机本机模式演示，口头说明异机待现场彩排 |
| token 被拒绝 | 停服务，重新生成至少 16 位且同时含字母与数字/符号的临时 token |
| Ollama 不可用 | 继续使用确定性词表/报告回退链；不声称已实测真实 LLM |
| 来不及处理任何技术问题 | 点击“填入合成演示文本”，完成校对、Validator、技师确认和导出 |

## 最能体现产品边界的对照演示

再用一段信息不完整的文本：

> 换了35微法电容。

预期结果：系统可记录更换动作、零件和规格，但不能自动写“1个”，也不能编造客户问题、检查结果、试机时长或“问题已解决”。页面应显示缺失项并追问。

这个对照比“AI 写得很流畅”更能说明系统的价值：它可以整理，但不代替技师补齐现场事实。

## 真实语音演示现状与剩余彩排

1. **已完成：** 项目内已准备 `whisper.cpp` `b4938` 与 multilingual Base 模型，二进制和模型均有 SHA-256 manifest。
2. **已完成：** 官方 `jfk.wav` 通过应用实际 `WhisperProvider` 返回正确 JSON 转写，本机单次约 1 秒。
3. **演示前必做：** 在主机 `127.0.0.1` 页面允许麦克风，使用非客户、非隐私的中文 HVAC 口述完成一次端到端彩排。
4. **仍未证明：** 中文口音、现场噪音、数字、否定词和零件规格的真实准确率。关键数值仍必须由技师核对。

## 让其他人用自己设备打开演示

代码已支持受控局域网模式，但受管沙箱内不能实际监听端口，因此尚未完成两台真实设备的现场验收。明天演示前必须在演示电脑和可信 Wi-Fi 上按上面的步骤做一次彩排；通过前只能声称“代码和安全回归测试已通过”，不能声称“异机网络已经实测”。

## 演示时不要声称

- 不要说“语音识别保证正确”。
- 不要说“AI 能诊断空调故障或判断安全”。
- 不要说“已用真实技师数据证明准确率”。
- 不要说“可以直接投入生产”。
- 不要把“Validator PASS”解释为现实世界的维修决策正确；它只说明报告没有超出已提供的事实。
