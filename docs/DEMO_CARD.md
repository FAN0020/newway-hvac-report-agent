# 明日演示卡（一页）

## 开场话（20 秒）

> 空调技师做完一单就要赶下一个地点，之后凭记忆补报告容易漏项。我们的 MVP 让技师口述或输入几个关键信息，系统把它整理成有来源的报告草稿。AI 不替技师诊断、报价或做安全决定，未经技师确认不能保存或导出。

## 上台前

1. 运行 `npm run stt:smoke` 和 `TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm run check`。
2. 最稳模式：`TMPDIR="$PWD/.tmp" npm_config_cache="$PWD/.cache/npm" npm start`，主机打开 `http://127.0.0.1:4310`。
3. 需要异机观看时，才使用长指南中的 LAN token + `npm run demo`；另一台设备麦克风不作为必演项。

## 推荐合成口述

> 客户反映不制冷。检查发现运刑电容损坏。更换了一个三十五微法电容。试机运行正常。问题已解决。建议下次保养清洗滤网。

这是合成演示数据，不含真实客户信息。

## 3 分钟演示顺序

1. 展示原始输入不会被覆盖。
2. 点击“检查术语修复候选”，并排展示原文与建议文本。
3. 逐项接受/拒绝；对 `35 µF` 勾选“关键值已人工核对”，填技师名称/ID。
4. 生成报告后指出：事实有来源 ID，缺失信息会显示，Validator 只验证“没超出已提供事实”。
5. 展示未确认时不能保存/导出；勾选技师复核并确认当前版本。
6. 导出文本或保存 JSON，强调报告变化后旧确认会失效。

## 失败时不停场

- 麦克风/Whisper 失败：点“填入合成演示文本”，改走手动原文；后续门禁完全相同。
- 手机打不开或不能录音：回主机 `127.0.0.1`，异机只展示手动流程。
- Ollama 不可用：使用已测的确定性回退链，不临场修模型。
- 任何不确定：直接用上面的合成文本完成“校对→报告→验证→人工确认→导出”。

## 不要过度承诺

- 不说“语音识别保证正确”或“中文 HVAC 准确率已验证”。
- 不说“手机麦克风、两台设备 Wi-Fi 已实测”。
- 不说“AI 能诊断故障、判断安全或自动报价”。
- 不说“已生产就绪”。准确说法是：**可提交的黑客松 MVP 源码，真实中文语音与异机现场验收待彩排。**
